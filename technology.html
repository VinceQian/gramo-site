Technology

Not a concept render.
A running prototype.

We assembled the spoon's internals, streamed real weight data over Bluetooth, and watched calories appear in a browser — the full hardware–software–data chain, working end to end.

Every layer, purposeful.

Sensing, compute, wireless, and power — engineered to fit inside a utensil.

Core Systems

Four systems, one seamless whole.

🧠

Custom Firmware & Chipset

Gramo runs on a Nordic nRF52840 Bluetooth Low Energy platform with our own firmware — sampling the sensor, packaging bite data, and streaming it in real time.

⚖️

Load-Cell Sensing

A high-precision load cell measures the mass of every spoonful. It's our most critical component — dual-sourced from two suppliers — and quantitative calibration is our current engineering focus.

📡

Bluetooth Data Chain

Bite data streams over BLE to the app. We've battled sensor drift and packet loss in testing — and built the reconnection and parsing logic to handle both gracefully.

🤖

Two-Stage AI Recognition

A photo of the plate goes through a two-stage recognition process that identifies the dish and maps it to calorie data — starting with a curated database done accurately, not a huge one done poorly.

Engineering Notes

What building it
taught us.

🎯

Debug the Cause, Not the Code

Facing sensor drift and Bluetooth packet loss, we learned to locate the root cause first — then fix it deliberately, instead of blindly rewriting code.

🔍

Verify Constraints First

Web Bluetooth's browser limitations cost us rework. Now every module starts with the same question: what does the environment allow — before a line of code is written.

📏

Narrow and Accurate Wins

We chose a curated food database with high accuracy over a huge one with shaky recognition — the same philosophy behind our free tier: do the basics reliably, differentiate on depth.
